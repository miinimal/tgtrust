# Decisions

- 2026-11-06 — Code lives in its own repository `miinimal/tgtrust` under the owner's personal developer account. Open developments are published from the owner's personal account.
- 2026-11-06 — Blind signatures: RFC 9474 RSABSSA-SHA384-PSSZERO-Deterministic. Standardised, output verifies with stock RSASSA-PSS, no extra dependencies beyond `cryptography`.
- 2026-11-06 — Issuer stores HMAC(pseudonym_key, epoch:bot_id:user_id), never raw ids. Raw ids are only ~52-bit, so an unkeyed hash would be brute-forceable.
- 2026-11-06 — Slot is recorded only after a successful blind signature; failed or forged requests never lock an account out.
- 2026-11-06 — Credentials are agent-bound, not bearer: the token commits to the agent key at issuance, so theft of a credential grants nothing. Rebinding to a new agent requires a new credential (new epoch or per-account allowance).
- 2026-11-06 — Path A (trusted issuer, light, phone-friendly) first; path B (signature verified inside a ZK proof, ~2–2.5M constraints for one Ed25519 check) after the pilot.
- 2026-11-06 — Contract language and toolchain for block 5. docs.ton.org (Tolk overview and Blueprint overview, read 2026-11-06) names Tolk the recommended language and Acton the recommended toolkit for new projects; Blueprint 0.47.1 (2026-09-30) no longer compiles Tolk — its Tolk templates only print the Acton command. Chosen path: Tolk 1.5.0 compiled directly with `@ton/tolk-js`, tests in TypeScript on `@ton/sandbox` 0.45.0 + `@ton/test-utils` 0.12.0, deployment scripts on `@ton/ton` 16.3.0. Reason: TypeScript tests give full control over time, bounces, balances and raw-storage invariants needed for cheating scenarios; Acton's tests are written in Tolk and its binary installer could not be run in the development environment. Acton can be adopted later for ABI wrappers and its proof-of-work faucet.
- 2026-11-06 — StakeRegistry money model: every outgoing payout is bounceable; a bounced payout is credited to `unclaimed[destination]` for the coins that actually returned and is retrievable with `Claim`. State changes always precede payouts. Gas requirements are computed from the live network config with gas-unit constants holding a ≥2× margin over measured usage; unspent gas stays on the contract as storage subsidy (Withdraw and Claim return the remainder to the sender).
- 2026-11-06 — Governance: admin and arbiter change in two steps (propose, accept by the proposed address after `changeDelaySeconds`); the contract rejects every message if `changeDelaySeconds < cooldownSeconds`, so stakers can always exit before a proposed arbiter takes office. Arbiter compromise remains the residual risk: production arbiter must be a multisig.
- 2026-11-06 — Agent consent for Deposit is `hash(cell(0x74677374, contractAddress, ownerAddress, agentKey, nonce))` signed with the agent key; replay on another contract or by another owner fails by construction, so nonces are not stored.
- 2026-11-06 — Testnet mnemonics live only in a local chmod-600 file loaded into environment variables per command; never in the repository. Testnet deployment uses demo parameters (minStake 0.5 GRAM, cooldown and change delay 120 s) solely to run the live cycle quickly.
- 2026-11-06 — Badge never exposes the stake owner's wallet (the contract keeps it; the badge publishes amount and state only). A stake without a registration yields level `unknown`: Gram alone proves nothing about who stands behind an agent. A withdrawing stake does not count as `staked`.
- 2026-11-06 — Stake lookups go through toncenter's public `runGetMethod` with the standard library and a short cache, so the issuer service gains no new dependencies; an API key is optional (`TGTRUST_TONCENTER_API_KEY`).
- 2026-11-06 — Deal records are signed by both agent keys over one canonical byte string with ordered keys, so a record has a single form and neither party can present a one-sided claim. The ledger stores the stake status of each party at submission: `deals with staked counterparties` is the count a bot should weigh, because every such deal had a counterparty with Gram at risk and a unique Telegram user behind it, which makes farming expensive. Amounts are informational (not verified against the chain).
- 2026-11-06 — The issuer service never holds the arbiter's TON wallet: verdicts are signed with a separate Ed25519 arbiter key and the on-chain `Slash` is sent from the arbiter wallet by its operator (`testnet.ts slash`). The contract's one-time case id guarantees a verdict is executed at most once; case ids are derived from (deal id, claimant), so retries are idempotent and a claimant gets one case per deal.
- 2026-11-06 — Dispute claimants name a payout address of their choice; it may be a fresh wallet, so the agent stays unlinked from its owner even when compensated.
