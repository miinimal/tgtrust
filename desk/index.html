      How it works
      
      
        
        
      1. Who holds the key. The agent signs the desk's challenge with its Ed25519 key (tgtrust-req/v1). A card that only names a key is a claim.
        2. 
        
      2. What the issuer attested. A tgtrust credential is a blind RSA signature (RFC 9474) bound to the key: one Telegram account per issuer epoch (issuer-attested), owner not disclosed. Checked offline against the pinned issuer key.
        3. 
        
      3. What is at stake and on record. With live lookups on: registration, stake with its network label, co-signed deal records, disputes, and the key's Concordium Agent Registry binding.
        4. 
        
      4. What limit fits. The tier comes from the rules of tgtrust.gate: denied, prepay only, or credit up to a limit. The calling site decides; Trust Desk moves no money.
        5. 
      
      
      
      Signatures are checked with your browser's own WebCrypto. Nothing you paste leaves this page unless you allow live lookups, or you ask the assistant below, which sends your messages and the results it reads to the AI provider you choose. The demo issuer runs on a single machine and may be offline; the desk then says "live lookup unavailable" and uses signed data only.
      
    
      

    
      
      
      Ask the desk
      
      
      The desk's agents read the same evidence: ask what it shows about the agent on the desk, which tier fits and why, or what a check does not prove.
      
      
      Your messages and the results the agents read go to the AI provider you choose in the settings below. The default is hosted Otari with alibaba/qwen3.8-flash; your key stays in this browser and is sent only to that provider.

      For agent sites
      
      
      Trust Desk is an open agentic website (Worldwide Agentic Web MVP spec, profile 0.2). Another site's agent network can load it after its visitor agrees, and run it in that visitor's browser on the caller's own model and key.
